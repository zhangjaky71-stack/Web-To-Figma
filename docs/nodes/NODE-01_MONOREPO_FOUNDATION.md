# NODE-01 — Monorepo Foundation

## Status

**DONE — GitHub Actions frozen-lockfile pipeline PASS**

## Goal

Create a reproducible, CI-enforced TypeScript monorepo foundation for the W2F browser extension, Figma plugin, and shared packages.

## Toolchain

- Node.js 24 LTS
- pnpm 11.22.0
- Turborepo 2.10.11
- TypeScript 6.0.3
- ESLint 10.8.1 + typescript-eslint 8.67.0
- Prettier 3.9.6
- Vitest 4.1.11

See `docs/adr/ADR-0001-node-pnpm-toolchain-and-lockfile-policy.md`.

## Workspace

```text
apps/
  browser-extension/
  figma-plugin/
packages/
  shared-utils/
```

Domain packages are created by their owning NODE to avoid empty architecture shells.

## Required Commands

```bash
pnpm install --frozen-lockfile
pnpm check
```

`pnpm check` covers foundation validation, lint, typecheck, tests, build, and formatting.

## Build Boundary

Each executable workspace has:

```text
tsconfig.json       — source + test typecheck context
tsconfig.build.json — source-only emitted build
```

Tests are excluded from production build output.

## Foundation Validator

`scripts/validate-foundation.mjs` protects:

- required workspace/config files;
- Node and pnpm pins;
- exact NODE-01 tool versions;
- root quality commands;
- Turborepo tasks;
- source-only build boundaries;
- shared-utils package export paths;
- `.wtf` and `application/x-wtf` contracts;
- rejection of obsolete MIME drift in current source and canonical docs;
- CI Node/pnpm versions;
- bootstrap versus frozen-lockfile state.

The validator was also corrected so its legacy-MIME guard does not accidentally match the validator's own implementation string.

## Authoritative Lockfile

The initial `pnpm-lock.yaml` was generated by GitHub Actions using:

- Node.js 24.19.0;
- pnpm 11.22.0;
- the four-workspace project graph.

After the lockfile was committed, CI was permanently switched to:

```bash
pnpm install --frozen-lockfile
```
